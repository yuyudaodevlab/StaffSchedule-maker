# 運営向けスケジュールメーカー

イベントの企画、会場ごとの実施枠、人物・グループ・ロールの担当を管理する、日本語の静的Webアプリです。温かいクリーム色とパステルカラーのデザインで、管理画面と閲覧専用の共有画面を提供します。

## 起動

Node.js 20.9以上（検証環境：24.12.0）を使用してください。

```sh
npm ci
npm run dev
```

開発画面は http://localhost:3000/ です。

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

`build` は `out/` にHTML・JavaScript・CSSを生成します。`preview` はその静的ファイルだけを配信する開発用のHTTPサーバーです。公開環境でNode.jsを常駐させる必要はありません。`file://` ではなくHTTP(S)で開いてください。

## 使い方

1. ホームでイベントを作成するか「サンプルを試す」を選択します。
2. 会場、グループ、人物、ロールを登録します。人物名は改行区切りで一括登録できます。
3. 「プログラム追加」から名前・開始・終了を入力します。会場、担当者、グループ、ロールは必要に応じて設定します。
4. タイムラインの空白をダブルクリックして追加、バーをクリックして詳細・編集、ドラッグで時刻変更、端をドラッグして実施時間を変更します。
5. ダッシュボードで重複・移動時間の警告を確認します。
6. 「共有する」で範囲と表示項目を選び、プレビューを確認してリンクを作成します。
7. 定期的に「エクスポート → 完全バックアップ」でJSONを保存してください。

### 日程と担当

- 日付タブの「＋」から日付の追加・コピー・削除ができます。日付の削除はその日に開始する枠を削除し、前日から継続する枠は残します。
- 開始・終了は日付付きです。23:30〜翌01:00のような予定も登録できます。
- 表示開始・終了の設定を超える予定がある日は、予定が見える範囲まで時間軸を自動で広げます。
- グループの全員参加と代表者参加を区別できます。人物は複数グループに所属できます。
- 担当時間が空欄の場合は実施枠の時間を使用します。音響などの前後に長い担当時間も設定できます。
- 同じ人物の複数ロールは担当行を追加します。
- 「別の実施枠を追加」は企画の名前・説明・色・メモを共有する会場別の枠を追加します。「複製」は独立した企画を作成します。
- ロール管理の「共有時の人物分類」で登壇者・出演者とスタッフを区別します。分類未設定の既存ロールはスタッフ扱いです。

### 編集補助

- Ctrl / Cmd を押しながらバーをクリックすると複数選択できます。一覧ではチェックボックスで選択します。
- 一括操作：時間シフト、後続枠シフト、複製、他日へのコピー・移動、会場変更、ステータス変更、人物・ロールの追加割り当て、削除。
- 一括操作は適用前に変更内容を表示します。後続枠シフトは、選択枠の最も早い開始時刻以降に開始する全会場の予定を対象にします。
- バーの右クリックから編集・複製・複数選択へ進めます。
- テンプレートは名前・所要時間・色を保持します。設定画面で編集でき、プログラム編集画面から保存できます。
- 空き時間の検索と拘束時間の集計はダッシュボードにあります。
- Undo / Redoは開いているプロジェクトの直近50操作を保持します。ブラウザ再読み込み後には引き継ぎません。

| ショートカット         | 操作                   |
| ---------------------- | ---------------------- |
| Ctrl / Cmd + S         | 保存                   |
| Ctrl / Cmd + Z         | Undo                   |
| Ctrl / Cmd + Shift + Z | Redo                   |
| Ctrl / Cmd + F         | アプリ内検索           |
| Escape                 | パネルを閉じる         |
| Delete                 | 選択枠の削除プレビュー |

文字入力中は標準の入力操作を優先します。スマートフォンはカード一覧・ボトムシート型のフォームで追加・編集でき、細かいドラッグ操作は必須ではありません。

## データと自動保存

- `Project` 内に `EventDay / Venue / Group / Person / Role / Program / Session / Assignment` を格納します。
- Programが企画情報、Sessionが会場・時刻・状態、Assignmentが担当者・グループ・実際のロール・拘束時間を保持します。人物行ごとに企画の複製データを作りません。
- 日時はUTCオフセットを持つISO日時です。表示・フォーム入力・日付移動はプロジェクトのIANAタイムゾーンを使用します。初期値は `Asia/Tokyo` です。
- 夏時間で存在しない、または二通りになるフォーム入力は拒否します。タイムゾーンを変更しても既存予定の絶対時刻は変更しません。
- IndexedDB（Dexie）へ変更後600msで保存します。プロジェクトを一つのレコードとして書き込み、関連データの途中状態を保存しません。書き込みは直列化します。
- 保存中・保存済み・保存失敗を表示します。未保存時のページ終了ではブラウザの離脱確認を使用します。
- 人物・グループ・ロール削除では担当参照を解除します。会場削除では会場未割り当てに戻します。最後の実施枠を削除した企画は削除します。
- JSON読み込みはZodで型・日時・ID重複・参照関係を検証してから適用します。統合は全IDを再生成します。未対応のスキーマバージョンは拒否します。
- 個別JSONは選択範囲の実施枠・担当・参照マスターを抽出します。これは管理用データです。外部配布には個別JSONではなく**共有用JSON**を使用してください。

ブラウザのデータ削除、プロファイルの破損、端末故障に備えてJSONバックアップを保存してください。ローカル保存は端末を保護する認証ではありません。同じプロジェクトを複数タブから同時に編集しないでください。

表示名の変更前から作成したプロジェクトを維持するため、IndexedDB名とテーマ保存キーには旧内部識別子を継続使用しています。画面のツール名とは独立しています。

## 共有

`/share/#s=...` のURLフラグメントに、共有対象だけを抽出したJSONをgzip圧縮し、Base64URL形式で格納します。ブラウザ標準のCompression Streamsを利用するため、圧縮ライブラリは追加していません。

- 共有データは管理用Projectとは別の、許可フィールドだけを持つ `ShareSnapshot` です。
- 人物・グループ・ロール・会場・日付・プログラムの条件を組み合わせられます。
- 名前、時刻、会場、登壇者名、スタッフ名、グループ、ロール、公開メモ、状態、タグ、運営時刻を選択できます。
- 非公開人物の名前、内部メモ、連絡先、担当メモ、マスターの備考、管理用IDは送出しません。
- 選択した人物以外のメンバーをグループ情報に紛れ込ませません。
- 自由記述のプログラム名や公開メモの内容自体は自動匿名化しません。プレビューで内容を確認してください。
- 閲覧画面はIndexedDBや元のプロジェクトを読み書きしません。
- URL作成後の元データの変更は反映されません。作成日時を共有画面に表示します。
- 閲覧者は受け取った範囲内で検索、一覧・タイムライン表示、詳細閲覧、PNG・ICS・共有JSON出力、印刷ができます。
- URLが8,000文字を超える場合は警告します。圧縮URL部分の上限は150,000文字、展開後の上限は2MBです。展開中もサイズ上限を監視します。
- 長いURLはアプリやメッセージサービスによって省略されるため、共有用JSONを渡し、共有画面から開いてもらってください。

リンクを知っている人は誰でも読めます。暗号化、認証、有効期限、取り消し、更新通知はありません。秘密情報の共有には使わないでください。

## ICS・PNG・印刷

### ICS

- RFC 5545形式のVEVENTを出力します。UID、DTSTAMP、UTCのDTSTART / DTEND、SUMMARY、DESCRIPTION、LOCATIONを含みます。
- 日本語、特殊文字、改行のエスケープ、CRLF、UTF-8の75オクテット折り返しを処理します。
- 管理画面からの出力は実施枠ごとに安定したUIDを使用します。取込元のUIDも保持します。
- UTC、TZID、VTIMEZONE、終日予定、浮動時刻に対応します。浮動時刻は取込先プロジェクトのタイムゾーンとして解釈します。
- 取り込みプレビューでエラー・重複UID・未対応内容を表示します。
- RRULE / RDATE / RECURRENCE-IDを持つ繰り返し予定は警告し、取り込みません。アラームやタスクは復元しません。
- Google / Apple / Outlookの実アプリとの相互運用は未検証です。標準形式での自アプリ往復をテストしています。完全な復元にはJSONを使用してください。

### PNG

専用Canvasレンダラーで全件を描画します。DOMのスクロール位置に依存しません。名前・担当・メモを折り返し、長い行と大量の予定は複数画像へ分割します。時間軸は各画像で共通です。

解像度1〜3倍、幅1,000 / 1,400 / 2,000px、文字サイズ、背景・ライト／ダークテーマ、余白、タイトル・日付・会場・公開メモ・凡例、目盛りの最小単位を設定できます。目盛りは文字が重ならない間隔へ自動調整します。画像の高さは4,000px以内、最大100枚に制限します。プレビュー後に各画像を保存できます。

出力画像は配布用の「プログラムと担当情報＋時間帯」レイアウトです。編集画面の会場→グループ→人物の階層をそのまま複写する形式ではありません。JPEG / WebP出力は未対応です。

### 印刷

A4 / A3、縦／横、余白、日付／会場ごとの改ページに対応します。表の見出しを繰り返す印刷専用CSSを使用します。「PDFとして保存」はブラウザの印刷画面から選択してください。用紙設定や改ページの最終結果はブラウザ・プリンタに依存します。

## 重複検知と集計の扱い

半開区間 `[start, end)` を使用し、終了と次の開始が同じ場合は重複扱いしません。人物の担当・集合・準備・リハーサル・撤収、会場の準備・転換・同時利用可能数・利用可能時間、人物の会場間移動時間・予定間隔を検査します。

中止した枠と「意図的な重複を許容」にした枠は重複警告の対象外です。意図的な重複は自動で判断しません。NOW / NEXTは時刻から計算し、手動ステータスを勝手に完了へ変更しません。

同じ人物が同じ実施枠を複数ロールで担当する場合、タイムラインと拘束時間は最も早い開始から最も遅い終了までの連続した拘束として扱います。途中の離席を正確に空き時間として扱いたい場合は実施枠を分割してください。会場の空き時間検索は予定のない時間を返し、残り定員の空き枠検索ではありません。

## 現在の制約・未対応の高度機能

- 会場の利用可能時間は一つの開始・終了範囲です。曜日別の複数営業枠や臨時閉鎖のカレンダーは未実装です。
- 会場間の移動時間は共通の分数です。会場ペア別の移動時間表はありません。
- バーのドラッグは時間の移動・伸縮です。会場・人物・ロールの変更はフォームか一括編集で行います。ドラッグ中の会場行への付け替えは未実装です。
- ミニマップは全体時間内の位置を示す移動スライダーです。全バーの縮小描画は未実装です。
- 会場別表示は会場フィルターを使う一覧です。準備・転換・撤収を独立した工程バーにする専用表示は未実装です。
- 重複警告は重複のある枠のうち最初の枠を開きます。複数の修正案を自動で最適化する機能はありません。
- テンプレートは名前・所要時間・色のみです。担当者セットや全運営項目のテンプレート化は未実装です。
- 旧スキーマ移行は将来のバージョン追加時に実装します。現時点ではv1だけを受け付け、追加した省略可能項目には既定値を補います。
- 50操作のUndoはメモリ上です。日をまたぐ操作監査ログやブラウザ再起動後の履歴復元は未実装です。

これらは画面上のダミー機能として表示していません。対応済みの代替操作を使用できます。

## 技術構成

- Next.js App Router / React / TypeScript strict
- Tailwind CSSとCSS変数によるテーマ・レスポンシブスタイル
- Radix Dialogによるフォーカス制御・キーボード対応（shadcn/uiと同じ基盤を直接利用）
- Lucide React / Motion（reduced-motion対応）
- Zustand / IndexedDB + Dexie / Zod
- Temporal polyfillによるタイムゾーン処理 / ICAL.jsによるICS解析
- Pointer Eventsによるタイムライン移動・伸縮。専用の座標計算に合わせ、dnd-kitは導入していません。

バージョンは `package.json` と `package-lock.json` で固定しています。Next.js 16.4.3 / React 19.3.1で型検査・静的ビルドとEdgeでのブラウザ検証を実施しています。外部フォント・画像・バックエンド・認証・API Routes・Server Actionsは利用しません。

実装参照：[Next.jsの導入要件](https://nextjs.org/docs/app/getting-started/installation)、[静的エクスポート](https://nextjs.org/docs/app/guides/static-exports)。

```text
src/app/             静的ルート、全体スタイル
src/components/      編集、一覧、管理、共有、入出力、印刷のUI
src/lib/model.ts     データ型・スキーマ・参照検証
src/lib/project.ts   プロジェクト操作・絞り込み・JSON部分抽出
src/lib/time.ts      タイムゾーン・日時・区間演算
src/lib/conflicts.ts 重複・拘束時間・空き時間
src/lib/editing.ts   一括編集の事前プレビュー
src/lib/sharing.ts   共有DTO・フィールド除外・圧縮・復元
src/lib/ics.ts       ICS入出力
src/lib/export.ts    画像描画・ダウンロード
src/stores/          保存キュー・Undo/Redo
```

## デプロイ

### GitHub Pages（サブディレクトリ）

ビルド時に `NEXT_PUBLIC_BASE_PATH=/リポジトリ名` を設定してください。末尾のスラッシュは付けません。

PowerShell：

```powershell
$env:NEXT_PUBLIC_BASE_PATH='/StaffSchedule-maker'
npm run build
```

bash：

```sh
NEXT_PUBLIC_BASE_PATH=/StaffSchedule-maker npm run build
```

`out/` 全体をPagesの配信アーティファクトとして公開します。GitHub Actionsでは `actions/configure-pages`（`static_site_generator: next` は指定せず `basePath` の自動上書きを回避）、ビルドステップの環境変数 `NEXT_PUBLIC_BASE_PATH: /${{ github.event.repository.name }}`、ビルド後の `out/.nojekyll` 生成、`actions/upload-pages-artifact` と `actions/deploy-pages` を使用します。これにより `_next/` や `/share/` が除外されず、共有リンクにも basePath が正確に反映されます。

### Cloudflare Pages / Netlify

ビルドコマンド：`npm run build`、公開ディレクトリ：`out`。ルート配信では `NEXT_PUBLIC_BASE_PATH` を設定しません。SSR用のNext.jsアダプターやサーバー機能は不要です。

全ルートに `trailingSlash: true` を設定しています。`/share/` と `/editor/` は事前生成されたHTMLです。SPA用の全URL書き換えは不要です。HTTPSで配信してください。

## 検証

```sh
npm run typecheck
npm test
npm run build
npm run preview
# 別のターミナル（Microsoft Edgeがある環境）
node scripts/browser-smoke.mjs
# 10会場・50グループ・300人・1,000予定のロジック確認
npx tsx scripts/performance-smoke.ts
```

自動テスト：日付またぎ、夏時間、半開区間、共通実施枠、複数ロール、会場容量、移動・撤収、JSON検証・ID再生成、ICS往復・UTF-8折り返し・TZID・重複UID、共有範囲・非公開項目・圧縮復元、IndexedDB保存・再読込・Undo/Redo。

ブラウザ確認：サンプル作成、固定列スクロール、追加・編集・再読込、人物別共有、共有の独立性、閲覧専用、PNG生成、スマートフォンからの追加。デスクトップと390px幅の画面を確認しています。ブラウザ検証の画像は `tests/*.png` に生成されます。

1,000予定の検証・重複検知は開発環境で確認していますが、特定の処理時間・フレームレートは保証しません。タイムラインの行・目盛り・画面外バーを表示範囲に応じて絞り、担当情報は実施枠ごとに索引化しています。実機のSafari / iOS / Android、大量データの長時間編集、外部カレンダーアプリ、実プリンタでの確認は別途必要です。
